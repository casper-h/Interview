# Coding Interview Preparation

Keep this track simple. Solve problems, understand failures, and revisit weak patterns. The repository does not prescribe a schedule, score, or tracker.

## Use the Track

1. Choose a core problem from [patterns](./patterns.md).
2. Attempt it under a 30 to 45-minute limit.
3. Identify the pattern and invariant before implementation.
4. Implement from reasoning rather than a memorized solution.
5. Test ordinary, boundary, invalid, and adversarial cases as the prompt permits.
6. Explain time and space complexity.
7. Review the root cause of any miss and revisit the problem later without notes.
8. Practice a follow-up constraint, such as streaming input, lower memory, concurrent updates, or a stricter complexity bound.

For the first pass, solve one core problem from each category in the order listed. Add a second core problem when you cannot state the invariant or implement the first reliably on a later attempt. Use reinforcement only after the pattern is recognizable without a category label.

Use the [playbook](./playbook.md) during timed practice. It covers clarification, approach selection, implementation, testing, communication, and optimization.

## What Mastery Means

You are ready to move beyond a pattern when you can recognize it in unfamiliar wording, derive why it works, implement it cleanly, test it, and adapt it after a constraint change. One successful solve is exposure, not mastery.

## Mixed Practice

After the core set is familiar, mix categories so the pattern is not given away. Use reinforcement and harder problems only to address a weakness or match a target company's current process. Continue coding mocks alongside system design and behavioural mocks.

The checked-in problem list contains no personal completion state. Keep attempt history privately.
